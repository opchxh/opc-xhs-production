# OPC 碎碎念探长小红书 Skill

这是一个给 Codex 使用的小红书内容生产全流程 Skill。它不是单独帮你写一段文案，也不是只做一个动效，而是把一条内容从“我有个想法”一路推进到：选题、口播稿、录制提示、素材收集、动效方案、成片动效、封面方案、封面提示词、小红书笔记正文、标签和最终发布包。

你可以把它理解成一个“自媒体制作总导演”。它会调用你已经常用的几个 Skill，把原本分散在不同对话里的工作串起来，并且每一步都有自检，避免漏步骤、乱编素材、没确认就开始生成。

## 适合谁

- 想用 Codex 做小红书、短视频、AI 教程、产品测评、经验分享的人。
- 不想每次都在灵造、Remotion、HyperFrames、封面 Skill 之间来回切换的人。
- 想把一条内容从选题直接推进到可发布素材包的人。
- 想固定一套自己的剪辑风格，并让 Agent 以后默认沿用的人。

## 触发方式

安装后，可以这样叫它：

```text
使用OPC 碎碎念探长小红书 skill
```

也可以直接说：

```text
沿用 OPC 碎碎念探长标准剪辑风格，帮我做这一期小红书内容。
```

## 核心功能

### 1. 从选题就开始接管

新版不再要求你必须先准备完整发布计划 MD。

你可以给它两种入口：

- 一份已有的发布计划 MD，里面包含口播规划和笔记规划。
- 一个比较粗的主题方向，比如“我想讲 Agent 和普通 ChatGPT 的区别”。

如果你只有方向，它会先整理成 intake brief，再交给 `lingzao` 做选题、脚本和内容包。

### 2. 调用灵造一次性做完前期内容

Lingzao 阶段不只是改口播稿，它会产出完整内容包：

- 选题方向与切入角度
- 原口播问题分析
- 新版口播稿
- 录制/拍摄提示
- 海报主标题
- 海报副标题
- 笔记正文主标题
- 笔记正文副标题
- 笔记内容
- 笔记标签

这样你不用自己先做选题、再写口播、再写笔记、再想封面标题。前期内容会集中在一个阶段完成。

### 3. 按顺序问你要素材

它不会一上来把所有素材都问一遍，而是按制作顺序收集：

1. 先问你有几段录音，并让你发送录音。
2. 收到录音后，再问你有几段真人视频，并让你发送视频。
3. 收到视频后，最后再问你有多少辅助素材，并让你发送截图、录屏、照片、B-roll 或链接。

素材会分别记录到 `audio_assets`、`video_assets`、`auxiliary_assets`，方便后面做动效和剪辑规划。

### 4. 只要求你拍必要的真人画面

默认不要求你录完整真人口播。

真人视频只建议拍这些：

- 开头出镜，用来建立信任感。
- 强调观点的地方，用来加强表达。
- 总结收口，用来让视频更有人味。

剩下的信息解释、流程拆解、案例说明，会主要交给动效和截图素材完成。

### 5. 固定默认剪辑风格

Skill 里已经内置默认风格：

```text
OPC 碎碎念探长标准剪辑风格
```

这个风格的核心是：

- 真人画面负责建立信任和强调观点。
- 动效负责讲清逻辑、结构、对比、案例和结论。
- 截图、录屏、照片、网页素材负责增强真实感。
- 默认比例大约是：真人 25%-40%，动效 40%-55%，截图/B-roll/辅助素材 10%-25%。
- 使用清晰章节进度、大标题、底部金句字幕和克制的整句字幕。
- 默认中间交付规格是 `1080x1920`、30fps、高码率 MP4，不默认做透明 MOV。

以后如果你给它新的成片参考，并明确说要换风格，它再学习新风格；否则默认沿用这套风格。

### 6. 动效前必须先给方案

收到素材后，它不会直接生成动效，而是先给你动效方案。

方案会包括：

- 这条视频想给观众什么感觉。
- 选择 Remotion 还是 HyperFrames，以及为什么。
- 每个场景的大致结构和时间安排。
- 会用哪些录音、真人视频和辅助素材。
- 是否需要从网上找补充画面或参考素材。
- 标准剪辑风格怎么落地。
- 字幕、标题、章节进度、画面层级怎么安排。
- 渲染和检查计划。

只有你确认之后，它才会进入动效生成。

### 7. 自动选择 Remotion 或 HyperFrames

动效阶段会根据任务选择工具：

- 需要 React/TypeScript、复杂时间轴、精细视频工程时，优先走 Remotion。
- 需要 HTML 动画、字幕、高效预览、网页式动效时，优先走 HyperFrames。

生成后会做渲染或预览检查，包括画面是否空白、比例是否正确、文字是否越界、字幕是否遮挡、关键帧是否拥挤。

### 8. 做封面前持续问答

封面阶段会调用 `atutun-xhs-cover-v2`。

它不会直接生成封面，而是先问你素材、标题、人设、禁忌和参考风格。收集完后，会先给封面方案：

- 主标题和副标题
- 3:4 首版构图
- 人物、产品或素材怎么摆
- 颜色、贴纸、箭头、勾选清单怎么用
- 字体层级怎么做
- 准备生成哪些版本

你确认后再生成。默认第一版是小红书常用的 3:4 竖版。

### 9. 最终整理发布包

最终会整理一份发布包，包含：

- 最终视频或动效渲染路径
- 封面路径
- 小红书标题
- 笔记正文
- 标签
- 发布检查清单

这样你不用在多个对话里翻找素材。

## 自检机制

这个 Skill 自带 `scripts/audit_episode.py`，每个阶段都可以检查一次。

它会避免这些常见问题：

- 没有 Lingzao 内容包就说前期完成。
- 没有用户确认就开始生成动效。
- 没有用户确认就开始生成封面。
- 编造录音、视频、素材、渲染文件路径。
- 漏掉音频、视频、辅助素材分类。
- 最终包缺封面、正文、标签或发布检查。
- 文档里还残留 TODO、TBD、示例路径等占位符。

## 安装

把 `opc-xhs-production/` 复制到 Codex 技能目录：

```bash
cp -R opc-xhs-production ~/.codex/skills/opc-xhs-production
```

## 验证

创建开发环境：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
```

运行官方 Skill 校验：

```bash
.venv/bin/python /path/to/quick_validate.py opc-xhs-production
```

运行本仓库自带测试：

```bash
python3 -m unittest skill-dev-tests/test_audit_episode.py
python3 skill-dev-tests/run_dry_skill.py
```

## 注意

不要提交真实 episode 素材、成片、账号 cookie、API key、`.env` 文件或私人草稿。仓库里的 `.gitignore` 已经默认排除了这些常见文件。
